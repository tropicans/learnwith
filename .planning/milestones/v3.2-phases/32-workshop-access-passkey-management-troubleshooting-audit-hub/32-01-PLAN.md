<title>Passkey Schema, In-Memory Store & Sliding-Window Rate Limiter</title>
<instruction>
Build the runtime data schemas, in-memory passkey store, and sliding-window rate-limiting engine:

1. Create `app/schemas/passkey.ts`:
   - Define and export Zod schemas and TypeScript interfaces:
     - `courseIdSchema`: `z.enum(['ai', 'word'])`.
     - `coursePasskeyRecordSchema`: `courseId` ('ai' | 'word'), `title` (string), `currentHash` (64-char hex SHA-256 string), `clearTextPreview` (string, masked preview e.g. "buk****ta"), `lastRotatedAt` (number timestamp), `rotatedBy` (string, e.g. 'master-admin'), `version` (number >= 1), `status` (z.enum(['active', 'deprecated'])).
     - `passkeyRotationHistoryEntrySchema`: `id` (string), `courseId` ('ai' | 'word'), `version` (number), `hash` (string), `rotatedAt` (number), `rotatedBy` (string), `reason` (string, optional).
     - `passkeyUnlockAttemptSchema`: `id` (string), `courseId` ('ai' | 'word'), `timestamp` (number), `clientId` (string), `ipAddress` (string, optional), `success` (boolean), `attemptHashPrefix` (first 8 hex chars of candidate hash, never store raw candidate), `failureReason` (string, optional), `rateLimited` (boolean, optional).
     - `rotatePasskeyInputSchema`: `courseId` ('ai' | 'word'), `newPasskey` (string min 6 chars, max 64 chars, trimmed), `reason` (string max 200 chars, optional).
     - `rotatePasskeyResultSchema`: `success` (boolean), `message` (string), `courseId` ('ai' | 'word'), `version` (number), `hashPreview` (string), `rotatedAt` (number).
     - `passkeyStatusResponseSchema`: `passkeys` (record of courseId to `CoursePasskeyRecord`), `recentAttempts` (array of `PasskeyUnlockAttempt`), `rotationHistory` (array of `PasskeyRotationHistoryEntry`), `stats` (`{ totalAttempts: number, successAttempts: number, failedAttempts: number, rateLimitedAttempts: number }`).
     - `passkeyAuditFilterSchema`: `courseId` (z.enum(['all', 'ai', 'word']).default('all')), `status` (z.enum(['all', 'success', 'failed', 'rate_limited']).default('all')), `search` (string, optional), `limit` (number default 50).

2. Create `app/server/passkeyStore.ts`:
   - Initialize default in-memory active passkeys seeded from `DEFAULT_AI_PASSKEY_HASH` and `DEFAULT_WORD_PASSKEY_HASH`:
     - Word Processing ASN (`word`): initial passkey `'buka-kata'`, hash `'ddf62f4013c59b111215312fb959629155a5b1dc5cf799f2053a8c2395c4511b'`, version 1, title `'Course 2: Pengolahan Kata ASN'`, masked preview `'buk****ta'`.
     - Agentic AI Workshop (`ai`): initial passkey `'buka-kelas'`, hash `'b99674726766354e30a414680548a5943f0ded595e286bec3355a016e87e362f'`, version 1, title `'Course 1: Hands-on Agentic AI'`, masked preview `'buk****as'`.
   - Seed initial rotation history entries and representative audit attempts for realistic visualization upon admin dashboard load.
   - Implement helper `maskPasskey(text: string): string`:
     - If text <= 4 chars: `'****'`.
     - If text > 4 chars: first 3 characters + `'****'` + last 2 characters.
   - Implement sliding-window rate limiter:
     - Map `clientFailureTracker = new Map<string, { timestamps: number[], cooldownUntil?: number }>()`.
     - Threshold: 5 failed attempts within 5 minutes (300,000 ms).
     - Cooldown duration: 2 minutes (120,000 ms) when threshold exceeded.
     - `checkRateLimit(clientId: string): { isLimited: boolean; remainingCooldownMs: number }`.
     - `recordFailedAttemptForClient(clientId: string): { isNowLimited: boolean; cooldownUntil?: number }`.
     - `resetClientFailures(clientId: string): void`.
   - Implement timing-safe verification:
     - `verifyPasskeyWithStore(courseId: 'ai' | 'word', candidate: string, clientId?: string, ipAddress?: string): { success: boolean; message: string; rateLimited?: boolean; cooldownRemainingMs?: number; unlockedAt?: number }`.
     - Checks rate limit first. If limited, logs attempt with `{ success: false, rateLimited: true, failureReason: 'Rate limit exceeded (cooldown active)' }` and returns throttled response.
     - Computes SHA-256 hash of `candidate.trim().toLowerCase()`.
     - Compares candidate hash against current store hash (or fallback static hash) via `crypto.timingSafeEqual` with buffer length check.
     - On match: logs success attempt, calls `resetClientFailures(clientId)`, returns `{ success: true, message: 'Passkey valid', unlockedAt: Date.now() }`.
     - On mismatch: calls `recordFailedAttemptForClient(clientId)`, logs failure with `attemptHashPrefix: candidateHash.substring(0, 8)`, returns `{ success: false, message: 'Passkey instruktur tidak valid.' }`.
   - Implement administrative methods:
     - `getPasskeyStatus(): PasskeyStatusResponse`: Returns current active passkeys, stats, recent attempts, and rotation history.
     - `rotatePasskey(input: RotatePasskeyInput, rotatedBy = 'master-admin'): RotatePasskeyResult`: Updates store hash and version, creates `PasskeyRotationHistoryEntry`, updates `lastRotatedAt` and `clearTextPreview`, and logs an admin rotation event.
     - `getPasskeyAuditLogs(filter?: PasskeyAuditFilter): PasskeyUnlockAttempt[]`: Returns filtered/searched attempts sorted newest first.
     - `clearPasskeyStoreForTesting()`: Resets store state to defaults for clean test execution.

3. Update `app/server/auth.ts`:
   - Update `verifyInstructorPasskeyFn` to call `verifyPasskeyWithStore(data.courseId, data.passkey, data.clientId || 'anonymous')`.
   - Update `app/schemas/serverFn.ts` to allow optional `clientId: z.string().optional()` on `verifyPasskeyInputSchema` and optional `rateLimited: z.boolean().optional()` on `verifyPasskeyResultSchema`.
</instruction>

<title>Passkey RPC Server Functions & Interactive Admin Passkey Console Components</title>
<instruction>
Build the admin RPC endpoints and modular UI components for Passkey Management inside `/admin`:

1. Create `app/server/passkey.ts`:
   - Implement `adminGetPasskeyStatusFn = createServerFn({ method: 'GET' })`:
     - Reads session token via `readSessionToken()` and validates with `validateAdminSession(token)`. If invalid, throws or returns `{ success: false, error: 'UNAUTHORIZED' }`.
     - Returns `getPasskeyStatus()`.
   - Implement `adminRotatePasskeyFn = createServerFn({ method: 'POST' })`:
     - Reads session token and validates admin session.
     - Validates input with `rotatePasskeyInputSchema.parse(data)`.
     - Calls `rotatePasskey(data, adminUser.role || 'master-admin')`.
     - Returns `RotatePasskeyResult`.
   - Implement `adminGetPasskeyAuditLogsFn = createServerFn({ method: 'GET' })`:
     - Reads session token and validates admin session.
     - Validates query filters with `passkeyAuditFilterSchema.parse(data)`.
     - Returns `getPasskeyAuditLogs(filter)`.

2. Build UI Components under `app/components/admin/passkeys/`:
   - `PasskeyStatusCards.tsx`:
     - Renders 2 featured cards for Course 2 (`word`) and Course 1 (`ai`).
     - Each card displays:
       - Course Badge & Title (`📝 Pengolahan Kata ASN` / `🤖 Agentic AI`).
       - Status badge (`Aktif • Versi X`).
       - Masked Passkey Preview with a toggle button to reveal cleartext if available or keep masked.
       - SHA-256 Hash Display (monospace, truncated with copy-to-clipboard button and tooltip).
       - Last rotated timestamp in Indonesian locale format (`d MMMM yyyy, HH:mm`).
       - Rotated by badge (`Oleh: Master Admin`).
       - Prominent action button: `"Rotasi Passkey 🔄"`.
   - `PasskeyRotateModal.tsx`:
     - Modal dialog triggered by clicking "Rotasi Passkey".
     - Fields:
       - Course selector / display (read-only based on card clicked).
       - Current active passkey preview and version notice.
       - New Passkey input (`type="password"` with show/hide toggle).
       - Minimum 6 characters validation message and strength hint.
       - Alasan Rotasi (opsional text input, e.g. "Pergantian Sesi Workshop Batch 2").
       - Warning banner: "Peserta workshop harus memasukkan passkey baru ini setelah rotasi dijalankan."
     - Actions: Batal and Simpan & Terapkan Rotasi (with loading state).
     - Calls `adminRotatePasskeyFn` and invokes `onSuccess()` callback.
   - `PasskeyHistoryTable.tsx`:
     - Table listing past rotation events: Versi, Modul Kursus, SHA-256 Hash Preview (first 16 chars), Waktu Rotasi, Dirotasi Oleh, Alasan.
   - `PasskeyAuditLogTable.tsx`:
     - Table showing unlock attempts (`ADMIN-PASS-03`):
       - Timestamp (formatted).
       - Modul Kursus pill (`word` vs `ai`).
       - Client ID (monospace tag).
       - Hash Prefix (monospace tag `attemptHashPrefix...`).
       - Hasil / Status: Green badge for `Berhasil`, Red badge for `Gagal`, Amber badge for `Rate Limited ⚠️`.
       - Keterangan / Alasan Gagal.
     - Filter toolbar:
       - Status filter: `Semua`, `Berhasil`, `Gagal`, `Rate Limited`.
       - Course filter: `Semua`, `Word Processing`, `Agentic AI`.
       - Search input for Client ID.
   - `AdminPasskeyView.tsx`:
     - Main view integrating `PasskeyStatusCards`, `PasskeyRotateModal`, `PasskeyHistoryTable`, and `PasskeyAuditLogTable`.
     - Summary KPI stats: Total Percobaan Unlock, Percobaan Berhasil, Percobaan Gagal, Percobaan Terblokir (Rate Limited).
     - Auto-refresh toggle (every 15s) + manual refresh button.

3. Update `app/components/admin/AdminShell.tsx`:
   - Replace placeholder card in `activeTab === 'passkeys'` with `<AdminPasskeyView />`.
