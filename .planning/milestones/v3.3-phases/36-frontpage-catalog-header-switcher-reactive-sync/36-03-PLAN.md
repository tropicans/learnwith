# Phase 36 — Plan 03: Direct Workspace Access UX, Passkey Preservation & In-Flight Protection

## Executive Summary
Enforce lifecycle state boundaries upon direct route access (`/course/ai`, `/course/word`) while delivering an exceptional, resilient user experience (`COURSE-SYNC-03`). Implement the accessible `CourseUnavailableNotice` component for soft-deleted (per D-09) and archived (per D-10) workshops, returning participants to the frontpage hub. Implement `UnlistedCourseBanner` to designate unlisted access (per D-11) while preserving full interactive workspace functionality and timing-safe passkey authentication on `/course/word`. Implement in-flight session protection (per D-15) to prevent mid-task UI teardown when an administrator changes status during active participant work. Wire SSR loaders in `app/routes/course.ai.tsx` and `app/routes/course.word.tsx` for zero client flash (per D-12) and validate the complete phase via `tests/course-lifecycle-sync.test.js` (per D-16).

---

<threat_model>
### ASVS Level 1 Threat Modeling

- **Threat Reference:** T-36-03 (Direct Route Bypasses & Passkey Gate Circumvention)
- **Threat Vector:** An unauthenticated or unauthorized user accessing direct URLs (`/course/word`) for hidden courses attempting to bypass the timing-safe passkey gate, or accessing deleted courses attempting to execute interactive exercises.
- **ASVS Control:** ASVS 4.0.3 v2.1.1 (Access verification on direct URL endpoints) and v5.1.3 (Lifecycle boundary enforcement).
- **Mitigation:**
  - Route loaders in `app/routes/course.ai.tsx` and `app/routes/course.word.tsx` evaluate lifecycle status during SSR, rendering `CourseUnavailableNotice` for `deleted` or `archived` states before any workspace modules can initialize.
  - For `hidden` courses, `app/routes/course.word.tsx` strictly maintains the `WordPasskeyModal` gate, ensuring that unlisted status never bypasses password verification.
  - Server-side APIs continue to validate session and passkey states independently of client navigation flags.
</threat_model>

<must_haves>
### Truths
- Direct access to a `deleted` course must render `CourseUnavailableNotice` with id `course-unavailable-deleted` and a link back to Beranda (`/`) (per D-09).
- Direct access to an `archived` course must render `CourseUnavailableNotice` with id `course-unavailable-archived` explaining that the workshop has concluded (per D-10).
- Direct access to a `hidden` course must render the workspace normally, with an `UnlistedCourseBanner` with id `banner-unlisted-course` indicating restricted access (per D-11).
- Direct access to a `hidden` `/course/word` workshop must preserve the timing-safe passkey prompt intact without bypass (per COURSE-SYNC-03).
- Lifecycle status must be checked in route loaders (`app/routes/course.ai.tsx` and `app/routes/course.word.tsx`) so the unavailable notice renders during SSR without client-side flash (per D-12).
- If an admin deactivates a course while a user is actively working (in-flight), the workspace must not be abruptly unmounted; instead, display an advisory notice banner with id `banner-inflight-status` (per D-15).
- Both `assets/css/components.css` and `public/assets/css/components.css` must remain 100% byte-for-byte identical.
