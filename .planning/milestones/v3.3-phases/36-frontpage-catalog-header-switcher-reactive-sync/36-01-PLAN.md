# Phase 36 — Plan 01: Server RPC Filtering & Frontpage Hub Catalog Sync

## Executive Summary
Establish the foundational server-side data boundary (`COURSE-MUTATE-03`) and frontpage hub catalog synchronization (`COURSE-SYNC-01`). Implement `getPublicCoursesListFn` in `app/server/courseLifecycle.ts` to strictly join catalog data with course lifecycle status so public consumers only receive `'active'` courses, preventing data leakage of hidden, archived, or soft-deleted workshops. Connect `app/routes/index.tsx` to this secure RPC and enhance `app/components/home/WorkshopCatalog.tsx` with friendly empty-state and category-empty experiences according to user decisions D-01 through D-04. Bootstrap the Phase 36 automated test suite in `tests/course-lifecycle-sync.test.js`.

---

<threat_model>
### ASVS Level 1 Threat Modeling

- **Threat Reference:** T-36-01 (Public Information Leakage & Catalog Snooping)
- **Threat Vector:** Unauthenticated external visitors or web scrapers inspecting SSR HTML or JSON payloads from `/` to discover drafts, internal training sessions, or soft-deleted courses.
- **ASVS Control:** ASVS 4.0.3 v5.1.3 (Server-side access control and data projection filtering).
- **Mitigation:**
  - `getPublicCoursesListFn` executes entirely on the server via TanStack Start `createServerFn({ method: 'GET' })`.
  - Joins static `getCoursesList()` with `getCourseLifecycleRecords()`, strictly dropping any record where `status !== 'active'`.
  - `app/routes/index.tsx` loader directly invokes `getPublicCoursesListFn()`, ensuring SSR markup only renders discoverable courses.
</threat_model>

---

<must_haves>
### Truths
- `getPublicCoursesListFn()` must return an array of `CourseData` containing only courses with status `'active'`.
- Courses in `'hidden'`, `'archived'`, or `'deleted'` state must NEVER be returned by `getPublicCoursesListFn()`.
- If 0 active courses exist in the store, `WorkshopCatalog` must render the friendly empty state card with id `catalog-empty-state` ("Belum ada workshop publik aktif saat ini") and a contact link (per D-03).
- If a category tab is selected that has 0 active courses while other categories have active courses, `WorkshopCatalog` must render the category empty state with id `catalog-category-empty` ("Belum ada modul aktif di kategori ini") without hiding the category tabs (per D-04).
- Both `assets/css/components.css` and `public/assets/css/components.css` must remain 100% byte-for-byte identical.

### Artifacts
- File: `tests/course-lifecycle-sync.test.js`
- Export: `getPublicCoursesListFn` in `app/server/courseLifecycle.ts`
- Component: Friendly Empty State Card and Category Empty Notice in `app/components/home/WorkshopCatalog.tsx`
- CSS Rules: `.catalog-empty-state-card`, `.catalog-category-empty` in `assets/css/components.css` and `public/assets/css/components.css`

### Key Links
- `app/server/courseLifecycle.ts` calls `getCoursesList()` from `app/data/courses.ts` and `getCourseLifecycleRecords()` from `app/server/courseLifecycleStore.ts`.
- `app/routes/index.tsx` invokes `getPublicCoursesListFn()` in its `loader`.
- `app/components/home/WorkshopCatalog.tsx` receives `courses: CourseData[]` and `activeFilter: string`.

### Prohibitions
- DO NOT perform client-side filtering for public catalog discovery; all filtering must occur server-side inside `getPublicCoursesListFn` before route loader returns data.
- DO NOT remove or hide category filter tabs when a category has 0 active courses; keep all tabs visible per D-04.
- DO NOT leave `assets/css/components.css` and `public/assets/css/components.css` out of sync.
</must_haves>
