# Plan 23-02: Production Docker Hardening, Multi-Stage Layering, Non-Root User & Signal Trapping

## Overview

Execute Wave 2 of Phase 23: harden the production Docker runtime on Node 20 Alpine. Implement CIS/OWASP compliant non-root execution (`USER node`), integrate `tini` as PID 1 to trap SIGTERM/SIGINT signals preventing container stop timeouts, configure native zero-dependency Node.js healthchecks, and optimize multi-stage build layering to ensure compact production images and rapid build caching.

<threat_model>
### Threat Modeling & Security Mitigations (ASVS Level 1)
- **T-23-01: Container Breakout / Privilege Escalation via Root Execution**
  - *Threat:* Running containers as default root user allows attackers who exploit an unpatched Node vulnerability or arbitrary code execution bug to gain root privileges on the host or access container host mounts.
  - *Mitigation:* Enforce `USER node` (UID 1000) in the runner stage of `Dockerfile` (per D-05). All application files in `/app` are explicitly owned by `node:node` via `COPY --chown=node:node`. Root execution is strictly disabled.
- **T-23-02: Zombie Process Accumulation & Ungraceful Shutdown Hang**
  - *Threat:* Node running as PID 1 fails to reap orphaned child processes and ignores standard SIGTERM signals from `docker stop`, forcing Docker to wait 10 seconds before issuing an ungraceful SIGKILL.
  - *Mitigation:* Package `/sbin/tini` into Alpine (`apk add --no-cache tini`) and set `ENTRYPOINT ["/sbin/tini", "--"]` (per D-08). Tini acts as a lightweight init process that reaps zombies and forwards termination signals immediately to Node.
- **T-23-05: Denial of Service via Missing Container Liveness Detection**
  - *Threat:* A stalled or hung Node event loop leaves the container reported as "running" by Docker, preventing automated orchestration failovers or health alerts.
  - *Mitigation:* Configure inline `HEALTHCHECK` with native Node `fetch` (`http://localhost:3173/`) executing every 15s with 3 retries (per D-06).
</threat_model>
