<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User Log Input → Client Redaction Engine | Untrusted terminal dumps, crash logs, and token strings entered into browser memory. |
| Redaction Regex Matching → Memory Execution | Regular expression evaluation against arbitrary user-provided input strings. |
| Export / Copy → Local Clipboard | Sanitized output copied to system clipboard for sharing in support channels. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-01 | Information Disclosure | `app/utils/redaction.ts` | Critical | mitigate | Mask all Telegram Bot tokens (`\b\d{8,10}:[A-Za-z0-9_-]{35}\b`), OpenAI keys (`\bsk-[A-Za-z0-9_-]{20,}\b`), Google Cloud / Gemini keys (`\bAIza[0-9A-Za-z-_]{35}\b`), Bearer tokens, emails, and Windows user paths (`C:\Users\[USER]\`). Pure client-side execution; zero network transmission of unredacted logs. |
| T-27-02 | Denial of Service | `app/utils/redaction.ts` | High | mitigate | Eliminate ReDoS (catastrophic backtracking) by strictly using bounded, linear quantifier patterns without nested repetition (`(a+)+`). Explicitly reset `rule.pattern.lastIndex = 0` on stateful global regexes. |
| T-27-03 | Information Disclosure | `app/data/pretrainingTroubleshooting.ts` | Medium | mitigate | Ensure no live production API keys or tokens are stored in the static troubleshooting cards; all sample commands use generic placeholders or localhost addresses (`http://localhost:20128`). |
</threat_model>

    Create `app/utils/redaction.ts` with:
    1. Interfaces:
       - `RedactionRule`: `{ name: string; pattern: RegExp; replacement: string }`
       - `SanitizeResult`: `{ sanitized: string; matchesCount: number }`
    2. Export `REDACTION_RULES`:
       - Telegram Bot Token: `/\b\d{8,10}:[A-Za-z0-9_-]{35}\b/g` -> `'[REDACTED_TELEGRAM_BOT_TOKEN]'`
       - OpenAI API Key: `/\bsk-[A-Za-z0-9_-]{20,}\b/g` -> `'[REDACTED_API_KEY]'`
       - Google Cloud API Key: `/\bAIza[0-9A-Za-z-_]{35}\b/g` -> `'[REDACTED_GOOGLE_API_KEY]'`
       - Bearer Token: `/Bearer\s+[A-Za-z0-9._~+/-]+=*/gi` -> `'Bearer [REDACTED_BEARER_TOKEN]'`
       - Email Address: `/\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b/g` -> `'[REDACTED_EMAIL]'`
       - Windows User Path: `/(C:\\Users\\)[a-zA-Z0-9_.-]+(\\)/gi` -> `'$1[USER]$2'`
    3. Export `sanitizeLogText(rawText: string | null | undefined): SanitizeResult`:
       - Return `{ sanitized: '', matchesCount: 0 }` for null, undefined, or empty string.
       - Loop through `REDACTION_RULES`, reset `rule.pattern.lastIndex = 0` before matching.
       - Count matches using `sanitized.match(rule.pattern)`.
       - Replace occurrences using `sanitized.replace(rule.pattern, rule.replacement)`.
       - Return final sanitized string and aggregated match count.
       - Ensure zero ReDoS vulnerabilities and strict client-side safety.
  </action>
