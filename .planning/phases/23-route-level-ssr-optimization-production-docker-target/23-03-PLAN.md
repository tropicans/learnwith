# Plan 23-03: Standalone Nitro Asset Caching, Automated Container Smoke Test & Multi-Tier Test Suite

## Overview

Execute Wave 3 of Phase 23: configure standalone Nitro static asset serving with immutable caching rules and gzip/brotli compression, deploy an automated container smoke test suite validating container health, non-root execution, and full document SSR payload integrity across all routes, integrate multi-tier testing scripts into `package.json`, guarantee 100% zero-regression across all 13 legacy unit test suites, and perform the multi-source coverage audit closing Milestone v3.0.

<threat_model>
### Threat Modeling & Security Mitigations (ASVS Level 1)
- **T-23-01: Container Breakout / Root Privilege Escalation Verification**
  - *Threat:* Accidental regressions in Dockerfile or deployment scripts could revert execution to root, exposing the host system.
  - *Mitigation:* Automated test in `tests/docker-smoke.test.js` executes `docker exec learnwith-app whoami` and asserts strict equality with `node`.
- **T-23-06: Cache Poisoning & Stale HTML Distribution**
  - *Threat:* Aggressive caching headers applied indiscriminately to dynamic SSR routes would cause users to receive stale or cross-contaminated server-rendered HTML.
  - *Mitigation:* In `app.config.ts`, route rules restrict `Cache-Control: public, max-age=31536000, immutable` strictly to content-hashed assets (`/_build/**` and `/assets/**`), while SSR responses from `app/ssr.tsx` explicitly set `no-cache, no-store, must-revalidate` (per D-10).
</threat_model>
