<threat_model>
### ASVS Level 1 Threat Modeling

- **Threat Reference:** T-37-01 (In-Memory Store Reference Pollution & State Bypass)
  - **Threat Vector:** Buggy or malicious code obtains a `CourseLifecycleRecord` via `getCourseLifecycleRecord()` and mutates `.status = 'deleted'` directly in memory, bypassing transition rules, version incrementation, and audit trails.
  - **ASVS Control:** ASVS 4.0.3 v5.1.4 (Memory safety and defensive data copy encapsulation).
  - **Mitigation:**
    - `getCourseLifecycleRecords()`, `getCourseLifecycleRecord()`, and `getCourseLifecycleAuditLog()` return defensive copies.
    - Automated unit and E2E tests tamper with returned objects and verify that store state remains pristine.

- **Threat Reference:** T-37-02 (Privilege Escalation & Unauthorized Mutation RPC Execution)
  - **Threat Vector:** Unauthenticated external visitors or standard workshop participants attempt to call `adminUpdateCourseStatusFn` or `adminGetCoursesLifecycleFn` using forged, expired, or non-admin session tokens.
  - **ASVS Control:** ASVS 4.0.3 v4.1.1 (Server-side role enforcement and access control validation).
  - **Mitigation:**
    - `assertAdminAuthorized()` strictly rejects undefined, null, empty, forged, expired, or non-admin participant tokens with `UNAUTHORIZED`.
    - Automated security boundary tests assert rejection across all invalid token archetypes.
</threat_model>

<must_haves>
### Truths
- Calling `getCourseLifecycleRecord('ai')` and mutating properties on the returned object must NOT alter the internal store state.
- Calling `getCourseLifecycleRecords()` and mutating array elements must NOT alter the internal store state.
- Calling `getCourseLifecycleAuditLog()` and mutating log entries must NOT alter the internal audit log entries.
- All 16 combinations of `(fromStatus, toStatus)` across `active`, `hidden`, `archived`, and `deleted` must be tested:
  - 14 allowable transitions (including no-ops and `deleted -> active` restore).
  - 2 disallowed transitions (`deleted -> hidden` and `deleted -> archived`) which must be rejected.
- Calling `adminUpdateCourseStatusFn` without a valid Master Admin session token must reject with `UNAUTHORIZED` or validation failure.
- Successful status mutations must increment `getCourseStoreVersion()` and append an audit record to `getCourseLifecycleAuditLog()`.
